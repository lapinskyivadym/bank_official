## 1. Вступ

### 1.1 Призначення
Документ визначає вимоги до вебзастосунку «ФінКит» — кабінету онлайн-банкінгу для фізичних осіб компанії «ФінКит Банк» — та до модуля бізнес-логіки нової функції «Кредитний калькулятор і заявка онлайн». Призначений для відділу забезпечення якості, розробників модуля та замовника як підстава приймання.

### 1.2 Обсяг
До обсягу входять функції кабінету клієнта від реєстрації до виходу та звернення до служби підтримки (розділ 3), а також правила модуля бізнес-логіки: кредитний калькулятор, валідатор переказів, книга обліку рахунку (розділ 5). Поза обсягом: мобільний застосунок, робочі місця операціоніста та ризик-менеджера, карткові продукти, сповіщення e-mail/SMS.

### 1.3 Терміни і скорочення

| Термін | Визначення |
| :--- | :--- |
| **Клієнт** | Фізична особа з обліковим записом у «ФінКит» і щонайменше одним рахунком. |
| **Кабінет клієнта** | Сторінки, доступні після входу: рахунки, операції, налаштування. |
| **Рахунок** | Поточний (checking) або ощадний (savings) рахунок клієнта з балансом у гривнях. |
| **IBAN** | Міжнародний номер банківського рахунку (International Bank Account Number); для України — «UA» і 27 цифр. |
| **Ануїтетний платіж** | Рівний щомісячний платіж за кредитом (частина основної суми плюс відсотки). |
| **Денний ліміт** | Найбільша сумарна сума переказів клієнта за календарну добу. |
| **Овердрафт** | Списання, після якого баланс рахунку став би від'ємним. |
| **РНОКПП** | Реєстраційний номер облікової картки платника податків (у поточній версії — поле SSN). |

### 1.4 Посилання
* Каталог продуктів — картка продукту П2 «ФінКит».
* Модуль бізнес-логіки «ФінКит» версії 1.0.0 — `README.md` у `docs/sprint2/`.
* Поточна версія продукту (demo): `parabank.parasoft.com`; резерв — `GlobalSQA Banking Project`.

## 2. Загальний опис

### 2.1 Користувачі та ролі

| Роль | Що робить у системі |
| :--- | :--- |
| **Клієнт** | Реєструється, входить і виконує всі операції кабінету за розділом 3. |
| **Операціоніст** | Обслуговує клієнтів у відділенні; у поточній версії окремого робочого місця не має. |
| **Ризик-менеджер** | Формує та затверджує правила кредитного скорингу та параметри автоматичного кредитного рішення (мінімальний баланс, спосіб оцінювання, поріг). |
| **Адміністратор** | Сторінка адміністрування: ініціалізація та очищення даних, режим доступу до даних, внесення затверджених параметрів кредитного рішення в конфігурацію системи. |

### 2.2 Середовище
Вебзастосунок для браузерів Chrome або Firefox: підтримка двох останніх стабільних версій (Current та Current-1) браузерів Google Chrome та Mozilla Firefox; поточна версія розгорнута за адресою з розділу 1.4. Модуль бізнес-логіки — бібліотека Java 17 (Maven 3.9, без зовнішніх залежностей у робочому коді; тести — JUnit 5).

### 2.3 Обмеження і припущення
1. Усі суми — у гривнях з точністю до копійки; символ «$» у поточній версії читати як «грн» 1:1.
2. Дані поточної версії періодично скидаються: створені під час тестування облікові записи і рахунки можуть зникнути.
3. Мова інтерфейсу поточної версії — англійська; підписи і повідомлення в документі — їх українські еквіваленти.
4. Поле «РНОКПП» відповідає полю SSN, «Область» — State, «Поштовий індекс» — Zip Code.
5. Параметри кредитного рішення (спосіб опрацювання заявки та поріг у відсотках) формує ризик-менеджер, а адміністратор вносить відповідні значення в конфігурацію на сторінці адміністрування; їх значення за замовчуванням не входять до документа.
6. Сповіщення e-mail та SMS не надсилаються; підтвердження показуються на сторінці.

## 5. Вимоги до бізнес-логіки модуля

Модуль — окремий Maven-проєкт (пакет `ua.kpi.tzyapz.finkit`, класи `LoanCalculator`, `TransferValidator`, `AccountLedger`). Усі грошові величини — тип `java.math.BigDecimal`; результати округлюються до двох знаків після коми (копійок) за правилом `HALF_UP`; проміжні обчислення не округлюються. Позначення: $P$ — сума кредиту (грн), $r$ — річна ставка (%), $n$ — строк (місяців), $i$ — місячна ставка у частках, $A$ — щомісячний платіж (грн).

| ID | Формулювання | Пріоритет |
| :--- | :--- | :--- |
| **BL-10** | `LoanCalculator.monthlyPayment(principal, annualRatePercent, months)` обчислює щомісячний ануїтетний платіж за формулою $A = P \cdot i / (1 - (1 + i)^{-n})$, де $i = r / 12 / 100$. Результат — `BigDecimal` із двома знаками після коми, округлення `HALF_UP`. | High |
| **BL-20** | `LoanCalculator.totalInterest(principal, annualRatePercent, months)` повертає загальну переплату $A \cdot n - P$, де $A$ — округлений результат BL-10; результат округлюється до двох знаків `HALF_UP`. | Medium |
| **BL-30** | Обидва методи `LoanCalculator` приймають лише $P$ у межах 1 000..1 000 000 грн, $n$ у межах 3..60 місяців, $r$ у межах 5..40 % (усі межі включно); для будь-якого значення поза межами метод кидає `IllegalArgumentException`. | High |
| **BL-40** | `TransferValidator.validate(fromIban, toIban, amount, balance, todaySpent)` дозволяє переказ лише за одночасного виконання умов: `amount > 0`; `amount ≤ balance`; `todaySpent + amount ≤ 50 000 грн` (денний ліміт); `fromIban ≠ toIban`. Результат — перелік кодів порушень (`AMOUNT_NOT_POSITIVE`, `INSUFFICIENT_FUNDS`, `DAILY_LIMIT_EXCEEDED`, `SAME_ACCOUNT`); порожній перелік означає, що переказ дозволено. | High |
| **BL-50** | IBAN рахунку-джерела та рахунку-одержувача має відповідати українському формату; рядок іншого вигляду вважається недійсним (коди `INVALID_FROM_IBAN`, `INVALID_TO_IBAN`). | High |
| **BL-60** | Перед перевіркою формату модуль валідує контрольні розряди IBAN за алгоритмом MOD-97 локально без звернення до зовнішніх мереж. | Medium |
| **BL-70** | `AccountLedger.deposit(amount)` збільшує баланс рахунку, `withdraw(amount)` — зменшує; сума кожної операції має бути додатною: для нульової або від'ємної суми метод кидає `IllegalArgumentException`; якщо сума `amount` перевищує `balance()`, метод `withdraw` кидає виняток `InsufficientFundsException`, а баланс залишається незмінним. `balance()` повертає поточний баланс. | High |
| **BL-80** | Клас `AccountLedger` є потокобезпечним (thread-safe): гарантує збереження узгодженого балансу при одночасному виконанні операцій `deposit` та `withdraw` у паралельних потоках; для некоректних даних кидає передбачені винятки `IllegalArgumentException` та `InsufficientFundsException`. | Medium |
